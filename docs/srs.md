# Star Everything 需求分析文档（SRS）

- 状态：V1 需求基线
- 产品名称：star_everything
- 适用对象：产品、设计、开发、测试

## 1. 产品概述

Star Everything 是单用户的个人收藏应用，用 URL、作者和可扩展标签保存、整理并查找跨平台内容。V1 首发可安装的 Linux `.deb` 与 Windows `.exe`；后续可考虑 macOS、Android 等平台。数据保存在本机，不要求账号、云服务或设备间自动同步；用户通过完整备份文件迁移数据。

AI-First 指研发流程中的人机协作和人工兜底，**不是**产品内置生成式 AI、Agent 或 MCP 功能。

## 2. 目标与范围

### 2.1 V1 目标

1. 快速保存作品 URL 或作者；至少提供其中一项。
2. 以 Home 为默认大收藏夹，支持嵌套收藏夹和多文件夹归属。
3. 使用平台、标题、作者、内容标签、收藏夹等信息搜索和筛选。
4. 尝试识别 Bilibili、抖音、小红书的分享链接/文案信息；失败时用户仍可手动补全并保存。
5. 提供本机结构化存储、完整导入/导出、设置和回收站。

### 2.2 V1 不做

- 用户账户、云端存储和自动同步。
- 关注作者更新、订阅 feed 或读取平台登录态。
- 产品内 AI、Agent/MCP 接口。
- 调用未公开签名接口、绕过验证码/反爬机制。
- 保证所有分享 URL 都能自动识别标题和作者。

## 3. 用户与核心概念

- **用户**：单个本机使用者。
- **收藏条目**：可包含网址、作者、标题、平台标签、内容标签和收藏夹归属的记录。网址与作者至少存在一项；作者可以不带 URL 单独收藏。
- **标签**：描述或定位收藏条目的可筛选信息。平台标签由用户维护；标题、作者和内容均可参与搜索/筛选。
- **收藏夹**：树形、可嵌套的组织位置；条目可以同时关联多个收藏夹。根收藏夹为 `Home`。
- **回收站**：暂存删除的条目/收藏夹树，可在保留期内恢复。

领域术语以 [`GLOSSARY.md`](../GLOSSARY.md) 为准。

## 4. 功能需求

### 4.1 收藏与标签

- 创建、查看、编辑、删除收藏条目。
- URL 与作者均可单独使用，也可同时使用；至少有一项非空才允许保存。
- 标题、URL、作者、平台、内容标签和文件夹归属均可搜索/筛选；可选标签不强制填写。
- 平台标签可由用户新增、改名、删除；预置 Bilibili、抖音、小红书标签，但不得限制用户新增其他平台。
- 内容标签以 `#标签` 录入，多个标签以空格分隔；可独立筛选与管理。
- 同一个 URL 可以存在多条不同收藏，不按 URL 自动去重。
- 作者可以作为收藏内容保存，不建立独立作者实体，不自动追踪更新。

### 4.2 收藏夹

- 初始提供根收藏夹 `Home`；首页默认展示 Home 中的收藏及全部收藏入口。
- 用户可创建、重命名、移动、嵌套和删除收藏夹。
- 收藏条目可以同时属于多个收藏夹；支持按收藏夹路径筛选。
- 筛选收藏夹时默认包含所选收藏夹的全部子孙收藏夹。
- 删除非空收藏夹时提供两种选择：
  1. 将其条目加入 Home 并删除所选收藏夹子树；条目仍保留在其他未删除的收藏夹中的关联。
  2. 将收藏夹子树及其条目移入回收站；从回收站恢复时整体恢复原目录结构与归属。
- 删除操作须明确展示影响范围并允许取消，避免误删。

### 4.3 搜索与筛选

- 搜索框检索所有文本字段：标题、URL、作者、平台标签、内容标签和收藏夹路径；采用不区分大小写的子串匹配。
- 同一筛选维度内多选值按 OR 匹配；不同维度之间按 AND 组合。
- 支持按平台标签、内容标签、收藏夹路径筛选；用户可添加和移除筛选条件。
- 清除筛选后回到默认收藏视图；无结果时允许用户修改查询或筛选条件。

### 4.4 元数据识别

- 用户可粘贴 URL 或平台分享文案；系统尝试识别平台、标题和作者，并允许用户在保存前修改结果。
- Bilibili：可尝试从无需登录的公开视频页面解析 `og:title`、`meta[name=author]` 等公开元数据；需识别人机验证/通用错误页，不能把错误页内容当作标题。
- 抖音：短链可尝试解析公开跳转；标题和作者优先从用户粘贴的分享文案提取。仅 URL 页面可能是无元数据 JS 壳，失败时请求用户补充分享文案或手动填写。
- 小红书：可尝试从用户粘贴的分享文案提取标题和作者；保留原始分享 URL 查询参数（例如 `xsec_token`），不得把带参数链接擅自改为裸 URL。页面验证/错误时不得伪造识别结果。
- 抓取仅使用公开可访问页面和用户主动提供的分享文案；不登录、不使用 cookies、不调用私有签名 API、不绕过验证码或反爬措施。
- 识别失败、离线或平台页面变化不得阻止创建/保存；用户可手动补录或修正。
- 不将 URL 查询参数（尤其访问令牌类参数）写入普通日志或错误遥测。

### 4.5 导入、导出与恢复

- 用户可导出完整版本化备份，至少包含收藏、标签、收藏夹树、设置和回收站状态。
- 导入前校验格式、版本和完整性；错误文件不得覆盖现有数据。
- 支持两种导入：
  - **合并**：按稳定记录 ID 合并，重复导入同一备份不增加同一记录；不同 ID 的相同 URL 收藏仍保留。
  - **替换**：完整替换本机数据及设置，执行前明确二次确认。
- 回收站项目默认保留 30 天；到期自动永久清理，并提供剩余时间提示和立即清空操作。
- 在保留期内可恢复已删除的收藏或收藏夹删除组；恢复收藏夹删除组时还原其层级和原归属。

### 4.6 设置

V1 设置至少包含：

- 数据完整导入/导出及替换确认。
- 平台标签管理。
- 元数据识别行为和手工补录入口。
- 基础主题设置。
- 回收站保留期状态、清理及恢复入口。

不提供账户、云同步或模型配置。

## 5. 数据与技术约束

- 技术栈：TypeScript、React、Tauri 2；Rust 用于桌面原生能力。
- 本地存储：使用 SQLite 结构化数据；按迁移版本升级 schema。选择依据是 Tauri SQL 插件为 SQLite 提供本地数据库访问、迁移，并覆盖 Linux/Windows 目标平台。
- 备份格式：版本化 JSON 数据包；导入导出不依赖私有云服务。
- 首发安装包：Linux `.deb` 与 Windows `.exe`，允许未签名；后续平台不属于 V1 验收。
- 网络仅用于用户主动的元数据识别；离线时收藏 CRUD、搜索、筛选、收藏夹和本地数据迁移仍可用。

## 6. 可用性与安全要求

- 删除、覆盖导入、清空回收站等不可逆/大范围操作必须有清楚的影响说明和确认步骤。
- 数据保存在用户设备；未经用户操作不得上传收藏、URL、作者、标签或备份。
- 任何平台识别失败均需保持原始 URL/分享文案可供用户编辑；识别内容需明确可编辑，不能静默覆盖已有人工修改。
- UI 文案应简洁，不常驻展示实现细节或业务规则；通过控件约束、校验与失败反馈表达限制。

## 7. 开发与质量保障

- 研发采用 AI-First 人机协作流程；AI 生成的实现由人工审阅，并通过自动化测试与格式检查，不在运行时把 AI 作为产品依赖。
- TypeScript/React 单元与组件测试：Vitest + React Testing Library。
- Rust 单元测试：`cargo test`。
- 格式化：Prettier（TypeScript/JSON/Markdown）与 `rustfmt`。
- 变异测试框架：StrykerJS（TypeScript）；用于标签解析、筛选组合、导入校验、回收站恢复和元数据解析等关键业务逻辑。V1 不引入 Rust 变异测试框架；Rust 仅承载 Tauri 原生启动/桥接代码，若后续加入实质业务逻辑再重新评估。
- 变异测试分数门槛尚未设定；先建立稳定基线，再确定阈值，避免为分数牺牲可维护性。

## 8. 验收摘要

- 可构建 Linux `.deb` 与 Windows `.exe`，二者共享核心收藏行为。
- URL-only、author-only 和 URL+author 条目均可创建；URL/作者都缺失时拒绝保存。
- 文件夹可嵌套，条目可多重归属；按既定规则筛选、移动、删除及恢复。
- 同 URL 条目允许重复；搜索覆盖所有文本字段；筛选组合符合 AND/OR 规则。
- 有效备份可合并/替换；损坏或不兼容备份不会损坏当前数据。
- Bilibili、抖音、小红书识别逻辑遵守公开数据边界；失败能手动补全并成功保存。
- 回收站项目在保留期内可恢复，30 天后自动清理。
- 格式检查、单元/组件测试、Rust 测试及针对核心逻辑的变异测试可运行。
